# AGENTS.md

Drovr: A kanban board for macOS and Linux where every card is a live terminal, for running many coding agents side by side.

Built with Software Factory's workflow: read `docs/agents/workflow.md` before starting on an item, and `docs/agents/stack.md` for the stack picked at creation and its guidelines. Domain terms are in `CONTEXT.md`, decisions in `docs/adr/`.

## Commands

- `npm ci` installs; `postinstall` rebuilds node-pty for Electron (needs python3, make and a C++ compiler on Linux). Where the Electron headers download is blocked (cloud sessions: postinstall fails with a proxy 403), everything else is installed by then: run `npm rebuild node-pty`; the Node build works in Electron too (N-API, ADR 0001). If `node_modules/electron/dist` is empty afterwards (the failed postinstall can skip Electron's own download), run `node node_modules/electron/install.js`.
- `npm run dev` starts the app with hot reload; `npm start` previews the production build. Both keep their data in `<appData>/drovr-dev` (`~/Library/Application Support/drovr-dev` on macOS), not the installed app's `drovr`, so they run beside it (`DROVR_USER_DATA_DIR` overrides).
- `.claude/check.sh` runs everything that must be green: typecheck, lint, Vitest, build, `node .factory/check-stack.mjs`. CI's `check` job runs it. Run as root (cloud sessions), the updater tests that make a folder read-only (`chmod 0555`) fail, since root writes it anyway: Vitest's "keeps the old app when its folder can't be written" and the smoke test "an install that can't swap the app". That is the sandbox, not the change; CI runs as a normal user.
- Individually: `npm run typecheck`, `npm run lint`, `npm test` (Vitest, with `SHELL=/bin/sh` from `vitest.config.ts`, so a developer's shell and its rc files never run in test PTYs), `npm run build`, `npm run format`.

In cloud sessions both fail at electron-builder's node-pty rebuild (the same proxy 403 as postinstall), and the failed rebuild deletes node-pty's build, breaking Vitest and any package built after it: run `npm run build && npx electron-builder -c.npmRebuild=false` (add `--dir` for the unpacked app) instead, and `npm rebuild node-pty` if it was already wiped.

To release, publish a GitHub release tagged `v<x.y.z>`, higher than the last; `package.json` keeps `0.0.1`.
- Locally, a failed electron-builder node-pty rebuild deletes node-pty's own build (`npm run dist`/`pack` and a bare `electron-builder`): pass `-c.npmRebuild=false` to try a package. node-pty then loads its bundled `prebuilds/<os>-<arch>` module.
- Headless launch: `xvfb-run -a npx electron . --no-sandbox` (after `npm run build`).

## Architecture

- `src/main` Electron main process; `src/preload` the only bridge to the renderer, typed by `src/shared/api.ts` (`window.drovr`); `src/renderer` React UI; `src/core` plain TS with no Electron imports (session/PTY logic), unit-tested with Vitest on Linux.
- `board` (#9): inside a card's terminal (only there), an agent runs `board move <card> <column>`, `board status <card> <text>`, `board activity <card> working|waiting|question|none` (#31: a pill on the card, runtime only, cleared on stop and start) or `board session <card> <uuid>` (run by Claude Code's hooks: the conversation the card resumes, saved); a worktree card's setup line (#39) runs `board setup . ok|failed` (not in `board help`; only for the calling card, another card's reads `has no setup running`; `ok` clears the card's pending setup and types its start line) (`.` is the calling card; `board help`). `resources/bin/board` (a POSIX sh wrapper; its directory is prepended to PATH in the environment of every card's shell and given as `DROVR_BIN`, so `"$DROVR_BIN/board"` works whatever a profile does to PATH) runs `out/main/board-cli.js` (built from `src/main/board-cli.ts`) with Drovr's own executable as Node; it talks to main over `<userData>/board/board.sock` (a private 0700 directory, the socket 0600), and main forwards each request to the renderer, which applies it to the store. Packaged, `bin/` is in `extraResources` and the CLI module and its chunks are unpacked from the asar (`electron-builder.yml`); after `npm run pack`, `dist/linux-unpacked/resources/bin/board` must be executable and `resources/app.asar.unpacked/out/main/board-cli.js` must exist. In SSH cards (#25) the local shell running `ssh` gets none of this: before each SSH session (main pane or extra pane) main listens on its own `<userData>/board/s-<16 hex>.sock`, serving only that card (`src/core/session-sockets.ts`), and the line becomes `ssh -o ExitOnForwardFailure=no -R /tmp/drovr-<32 hex>.sock:<that socket> -t -- …` (`src/core/ssh-command.ts`); the remote command writes a POSIX sh `board` script running an embedded perl or python3 client (`src/core/remote-board.ts`, no backslashes so it stays fish-safe) into a private `mktemp -d` directory and removes it and the remote socket when the shell ends. Claude Code cards (#31 D14) start `claude --settings "$DROVR_CLAUDE_SETTINGS"`: every card's shell gets `DROVR_CLAUDE_SETTINGS`, locally `resources/bin/claude-settings.json` (hooks calling `board activity`, and a SessionStart hook printing `claude-instruction.txt`); both files are generated from `src/core/claude-hooks.ts` and a test keeps them equal; the SSH remote command writes copies beside the remote `board` (the JSON's backslashes printed by `awk`, so the command keeps none). Session sockets close when their session exits and on quit; leftovers are removed at launch. Without a local socket ssh gets no `-R`, and the card runs anyway.
- Terminal themes: `src/core/ghostty-themes.json` is Ghostty's 463 theme files (iTerm2-Color-Schemes), rebuilt with `node scripts/import-ghostty-themes.mjs <ghostty>/themes`; "Use Ghostty theme" reads the user's Ghostty config in main (`src/core/ghostty-config.ts`). The bundled `Symbols Nerd Font Mono` (`src/renderer/src/assets/fonts`) is loaded before the first render and appended to every terminal's font family. Their licences are in `THIRD_PARTY_NOTICES` (packaged by `electron-builder.yml`'s `extraResources`): update it when either changes.
- Terminal and agent preferences (`Preferences` in `src/core/settings.ts`: cursor, scrollback, line height, letter spacing, bell, copy on select, Option as Meta, bold bright, notifications, Claude Code status) are one table of defaults and checks; each is written to `drovr-settings.json` only when it differs from its default. Notifications (`src/renderer/src/attention.ts`) watch every card's activity through `CardSessions.onActivity`, and keep the waiting queue (#41: cards and shells waiting for the user, oldest first, with `subscribeWaiting`/`useWaitingQueue` for the sidebar counts and the palette; picking the next one and the counts are `src/core/waiting.ts`), and every screen's ended commands (#45 D7: `onScreenCreated` in `card-terminals.ts` gives each new screen with its card and pane, `longCommandNotice` in `src/core/long-commands.ts` decides; the threshold reaches the renderer as `window.drovr.longCommandMs`, from `DROVR_LONG_COMMAND_MS` in the development build only, passed as a renderer argument); main sets the Dock badge, focuses the window and asks for attention (`src/main/attention.ts`). The Claude Code status switch reaches the session start hook as `DROVR_CLAUDE_STATUS` (local env, or exported by the SSH remote command).
- Worktree cards: main runs `git` and `cp` with `execFile` (no shell) through `src/core/worktrees.ts`, whose commands are injected so `worktrees.test.ts` drives real throwaway repositories; worktrees live in `<userData>/worktrees`, and main only checks or removes paths inside it (`src/main/worktrees.ts`). Branch names come from `src/core/worktree-names.ts`. Name test fixtures for ignored files something like `local.conf`: the secrets hook blocks any command that touches dotenv files.
- Branch menu (#33): the title bar's branch chip opens it (`src/renderer/src/BranchMenu.tsx`), acting on the open worktree card's directory, else the workspace folder; local workspaces only. `src/core/git.ts` lists, switches and creates branches, fetches (`--all --prune`), pulls (`--ff-only`; without an upstream it first tracks the remote branch of the same name, `origin`'s else the only remote's, and with no remote Fetch and Pull say so), pushes (`--set-upstream origin refs/heads/<branch>` without an upstream, never forced) and reads ahead/behind (`rev-list --left-right --count HEAD...@{upstream}`) with git injected (`GitRunner`), every command with the no-prompt environment (`gitEnv`: `GIT_TERMINAL_PROMPT=0`, no askpass, ssh in batch mode, the user's `GIT_SSH_COMMAND`, `core.sshCommand` or `GIT_SSH` kept), a 2-minute timeout and stdin closed, run by `spawnRunner` off Windows `detached` (its own session, no controlling terminal, so ssh can't ask on `/dev/tty` even under a plain `GIT_SSH`; `execFile` ignores `detached`, so it uses `spawn`; the timeout ends the whole process group), and `gitError` turning stderr into the menu's error line (hints, progress and ref-update lines dropped, ssh's or the remote's cause kept, the end kept past 400 characters; with a credential hint when git or ssh needed a password or key, `git timed out` at the limit); Fetch, Pull and Push keep the menu open with a note (`Fetched`, `Pulled`, `Already up to date`, `Pushed`), one command at a time per folder with every action disabled in every chip for it, its busy label and last note or error kept outside the chip (`src/renderer/src/git-runs.ts`), and main queues the menu's commands per folder; the current branch comes from `symbolic-ref --quiet HEAD` (not `--short`, which gives `heads/v1` beside a tag `v1`) and a remote branch is tracked from `refs/remotes/<remote>/<branch>`; `useBranch` is undefined until first read, null outside a repository; `git.test.ts` drives real throwaway repositories with a local bare remote. Main (`src/main/git.ts`, main frame only) runs it in an absolute existing folder, and only on branch names git itself lists.
- Worktree card pull requests and merges (#38): a worktree card's ⋯ menu has Open pull request (`pushForPullRequest` in `src/core/pull-requests.ts`: #33's `push`, then the compare URL main builds from a GitHub remote, or the open PR's own URL from main's last `gh` read; the renderer only names the folder and never hands main a URL to open) and Merge into `<branch>` (`mergeCardBranch` in `src/core/merges.ts`, run in the workspace folder queued with its other git commands; main reads both branches itself and refuses if they differ from what the confirmation named; a conflict is aborted). The PR chip reads `gh pr view` through the user's login shell (`src/core/pr-status.ts`, as #55's editor runs), any failure meaning no PR. IPC `git:openPullRequest`, `git:pullRequest`, `git:merge` in `src/main/git.ts` (main frame only); the card's action line is `src/renderer/src/card-git.ts`, its PR reads `src/renderer/src/pull-requests.ts`. A tool run through the login shell shares stdout with whatever the profile prints: parse only the tool's own output (gh's JSON is the last line starting with `{`). An e2e test proving a tool is missing must leave only the fake `bin` on the login PATH: GitHub's ubuntu runners have `gh` in `/usr/bin`.

- Automatic moves (#42): a workspace's `autoMove` rules (column ids, `src/core/auto-move.ts`: `readAutoMove` for the state and sync files, `autoMoveTarget` for the decision) are applied in the renderer (`src/renderer/src/auto-move.ts`) from `CardSessions`' activity and ended events, moving cards through the store like `board move`. - Terminal flow control (#16): main pauses a PTY above 100k characters the renderer hasn't acknowledged (`terminal:ack`, sent once xterm has parsed them) and resumes below 5k (`src/core/flow-control.ts`). Every chunk the renderer receives must be acknowledged exactly once (`SessionRouter` + `AckBatcher`), or its shell stays paused. node-pty drops a paused PTY's unread output 200 ms after its shell exits, so `SessionManager` resumes before kill and resumes a paused session whose shell is gone.
- Sync folder I/O (#26): never block main on the sync folder (it may be a stalled network mount or a cloud placeholder). `SyncFolder` uses async fs and runs every operation one at a time on its own queue, so a new operation must go through that queue to keep #13 D4 (no echo) and D12 (never overwrite). A libuv thread stuck in a stalled fs call keeps the process from exiting, so quit SIGKILLs main when sync is still busy at `quit` (`src/core/quit-hold.ts`).
