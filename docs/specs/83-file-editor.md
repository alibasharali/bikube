# File editor

## Problem

Opening a file from the side panel's Files tab, the Agent tab or Agent setup today always runs an external editor (Settings > Editor), so checking or tweaking a file means leaving Bikube for VS Code. After this ships, those files open in Bikube's own editor: a per-workspace view in the main area with tabs, syntax highlighting for the common languages, Markdown rendered by default, images shown as pictures, explicit saving with conflict handling, and unsaved edits kept across a quit. The external editor stays one menu item away.

Grilled in two rounds on the item page (round 1: library, placement, relation to Settings > Editor, tabs, Markdown, saving, limits, entry points; round 2: sidebar rows, drafts at quit, restart, shortcuts, Markdown library, look, files outside the folder, palette).

## Domain decisions

- **D1 – Editor component:** CodeMirror 6 (`@codemirror/state`, `view`, `commands`, `language`, `language-data`, `search`, `@lezer/highlight`), languages from `@codemirror/language-data` loaded lazily by file name and extension (chunks served from `'self'`, so the CSP is unchanged: CodeMirror's injected styles fall under the existing `style-src 'unsafe-inline'`). A file with no known language opens as plain text. *Why:* light, modular, themable with our tokens (round 1 Q1); Monaco needs workers and CSP changes, Shiki can't edit.
- **D2 – Its own view:** the editor is a workspace's fourth main-area view beside its board, an open card and Agent setup: view memory gains `{ kind: 'files' }` (runtime only, like the others). Opening a file shows the view with that file's tab active; opening a card, Agent setup or the board replaces the view in front without closing any tab; Back returns to the board; clicking the active workspace's own row forgets it, as today. Main window only: a card window (#53) has no editor view. *Why:* round 1 Q2, the Agent setup pattern; not card windows (round 1 Q8).
- **D3 – Tabs, runtime only:** each workspace keeps an ordered list of open files (App state, like `openSetups`) and its active tab. A tab is identified by the file's absolute real path, so opening the same file from the Files tab, the Agent tab or Agent setup focuses the one tab. A new tab goes right of the active one. Clean tabs are never saved: after a restart a workspace has no tabs, except those restored as drafts (D11). Deleting a workspace closes its tabs. *Why:* round 1 Q4, round 2 Q3.
- **D4 – Sidebar rows:** in the sidebar tree each open file is a row under its workspace, after its terminals and Agent setup's row, in tab order: the file's icon (`fileIcon`), its name, a dot while dirty, its path (relative to the workspace folder, else with `~`) as the tooltip, marked current while its tab is in front. A click makes its workspace active, shows the editor view and selects that tab. File rows hold no Ctrl+digit number and aren't in Split's Agents section (they stay nested under their workspace in Split too) or the collapsed sidebar. *Why:* round 2 Q1 picked one row per file.
- **D5 – Opening a file:** Enter or double-click on a file in the main window's Files tab opens it in the editor (D2) instead of the external editor. Every file row gains a ⋯ menu (shown on hover and focus, and on right-click) whose item **Open in <editor>** runs today's `files:open` with Settings > Editor (`Open in VS Code`, `Open in Cursor`, `Open in Zed`, `Open with default app` for System, `Open with custom command` for Custom). In a card window's Files tab Enter and double-click keep running the external editor, and the menu is the same. The Agent tab's What changed rows and Files and artifacts rows for a file inside the card's or shell's folder open in the editor (outside ones keep today's `shell.openPath`); Agent setup's Open file opens its listed file in the editor, editable, even outside the workspace folder (`~/.claude/settings.json`, user skills), and its Reveal is unchanged. *Why:* round 1 Q3, Q8; round 2 Q7.
- **D6 – File access in main:** the renderer never reads or writes files itself. A tab holds a reference main checks on every request: `{ kind: 'folder', folder, path }` (a path relative to a shown folder, checked by `insideFolder` by real path, as `files:list`) or `{ kind: 'listed', folder, path }` (an absolute path Agent setup's last read of that folder listed, `ListedPaths`, as `agentSetup:open`). Main frame only; anything else is refused before any read. Reads and writes go to the real path, so a symlink inside the folder edits its target and stays a link. A Node-free module holds the shapes; an fs-injected core module holds the read, stat and write logic with Vitest on temp folders.
- **D7 – What opens and how:** by extension, `png`, `jpg`, `jpeg`, `gif`, `webp` and `svg` show as a picture (a `data:` URL in an `<img>`, so an SVG runs no script; up to 20 MB), with Open in <editor> in the header. Any other file up to 5 MB (5,242,880 bytes) is text when it has no NUL byte and decodes as UTF-8 (a BOM kept and written back); its line endings are detected (CRLF when the first line break is CRLF) and written back the same. A file with a NUL byte or invalid UTF-8 shows `Binary file` with Open in <editor>; a larger file shows `Too large to open here (<size>)` with Open in <editor>; a missing one `File not found`. *Why:* round 1 Q7.
- **D8 – Look:** the editor uses the effective terminal font family and size (`useEffectiveSettings`, Ghostty config included), line numbers, the terminal theme's background as its background and the terminal theme's ANSI colours for syntax (keywords magenta, strings green, numbers and constants yellow, comments bright black, functions blue, types and tags cyan, the rest the foreground), so every terminal theme and Light/Dark reads like the terminal next to it; the chrome around it (tabs, header, bars) uses the app theme's tokens. Soft wrap is a header toggle saved as the preference `editorWrap` (default off, written only when on). The side panel stays beside the editor view, with Toggle panel working. *Why:* round 2 Q6; the terminal theme's colours already hold on its background, so no new per-app-theme tokens.
- **D9 – Header:** above the editor, the tab strip (each tab: icon, name, dirty dot, × on hover, focus and the active tab; a name shared by two tabs adds its parent folder), then a header line: the path (as D4), Markdown's Preview / Edit toggle (D10), Wrap, and Open in <editor> (for a listed file outside the folder, the editor runs with the file's own folder as the project folder, as `openListedFile` does). The view has a close button (`file-editor-close`) closing every tab (D12's question for each dirty one first).
- **D10 – Markdown:** `.md` and `.markdown` open in Preview, rendered by markdown-it (CommonMark, tables, strikethrough, linkify; `html: false` so raw HTML shows as text; task list items `- [ ]`/`- [x]` as disabled checkboxes by a small rule of our own), fenced code highlighted with D1's languages and D8's colours. Links: `http`/`https` open through `link:open`; a relative link to a file inside the same reference's folder opens it in a tab; `#anchor` scrolls the preview; anything else does nothing. Relative images inside the folder load through D6 as `data:` URLs (D7's limits); others show their alt text. Preview / Edit is per tab, kept while it's open; Preview re-renders from the tab's current text, dirty or not. *Why:* round 1 Q5, round 2 Q5.
- **D11 – Drafts:** a dirty tab's text is saved on this machine 2 s after its last edit and at `app:quitting` (main waits for it within `QUIT_SAVE_WAIT_MS`, as kept output) as `<userData>/drafts/<sha256 of workspace id + real path>` (folder 0700, file 0600, written to `.tmp` and renamed): its workspace id, reference, text, line ending, BOM and the file's base (size, mtime, SHA-256 when read). At launch each draft whose workspace exists reopens its tab dirty (the workspace still showing its board, the rows in the sidebar); a draft whose workspace is gone is deleted; then D13's check runs against its base, and a file that is gone shows the bar `Deleted on disk` with Save (writes it again where its folder still exists) and Discard. A draft is deleted when its tab is saved, discarded or closed. Never in `bikube-state.json` or the Sync folder. *Why:* round 2 Q2: the app never cancels a quit.
- **D12 – Saving and closing:** Mod+S saves the tab in front (fixed, not in Settings), only while the editor view shows. A save writes only when the file still matches the tab's base (size, mtime and hash); else it writes nothing and shows D13's bar. A write goes to a `.tmp` beside the file, keeping its mode, renamed over it. A failed write keeps the tab dirty with `Couldn't save <name>: <reason>` under the header. Closing a dirty tab (its ×, Close pane's shortcut, the palette) asks `Save changes to <name>?` with Save, Discard and Cancel; the view's close button asks for each dirty tab in turn, stopping at Cancel. Deleting a workspace with dirty tabs adds `<n> unsaved files will be discarded` to its confirmation.
- **D13 – Changed on disk:** each open text tab's file is checked (stat, then a re-read when size or mtime changed, comparing the hash) every 3 s while any Bikube window is focused, on focus and before a save. A clean tab whose file changed reloads silently, keeping the cursor line and scroll where they still exist. A dirty one shows the bar `<name> changed on disk` with Reload (drops the edits) and Keep mine (takes the disk version as the new base, so the next save overwrites it); it shows once per change. A file that disappears marks a clean tab `Deleted on disk` (the tab stays, read-only, with Close) and a dirty tab with D11's bar. *Why:* round 1 Q6.
- **D14 – Shortcuts:** while the editor view shows, Close pane closes the active tab (the last tab closed returns to the board), Find opens CodeMirror's search panel (themed with the app's tokens; in Preview it first switches to Edit), Back returns to the board, Toggle panel toggles the side panel. The app's shortcuts are handled before CodeMirror's keymap; CodeMirror keeps its own defaults (undo, indent, comment) otherwise. No new configurable shortcuts. *Why:* round 2 Q4.
- **D15 – Palette:** while the editor view shows, the palette lists `Save file`, `Close tab`, `Markdown: Preview` or `Markdown: Edit` (a Markdown tab), `Toggle wrap` and D5's `Open in <editor>`; every open file is a row like cards and shells (`<name>` with its workspace, after the shells), opening its tab. `board palette list` and `run` (#81 D23) leave out the open files' rows and the editor's view rows, as they do the open card's. *Why:* round 2 Q8.

## Acceptance criteria

- **AC1 – Open from Files:** Given a local workspace with `src/a.ts`, when the user double-clicks it (or selects it and presses Enter) in the main window's Files tab, then the editor view replaces the board with one tab `a.ts`, the file's text with line numbers and TypeScript highlighting (a keyword span coloured differently from a string), the terminal font family and size, and a sidebar row `a.ts` under the workspace marked current; no external editor runs (a fake `code` on the login PATH logs nothing).
- **AC2 – Open in <editor>:** Given Settings > Editor at VS Code and a fake `code`, when the user opens `a.ts`'s ⋯ menu (hover or right-click) and picks `Open in VS Code`, then the fake `code` logs the folder and the file, and no tab opens; in a card window's Files tab a double-click runs the fake `code` too.
- **AC3 – Tabs and rows:** Given `a.ts` open, when the user opens `b.md` and then `a.ts` again from the Files tab, then there are two tabs and two sidebar rows (`a.ts`, `b.md`), `a.ts` is active, and the sidebar's `b.md` row click shows `b.md`'s tab. Opening a card, then clicking `a.ts`'s row, brings the editor back with both tabs; Back shows the board with both rows still in the sidebar.
- **AC4 – Save:** Given `a.ts` open, when the user types `x` then presses Mod+S, then the tab's dirty dot appears after typing and goes after the save, and the file on disk holds the new text with its original CRLF line endings kept for a CRLF file.
- **AC5 – Close dirty:** Given `a.ts` dirty, when the user presses the Close pane shortcut, then `Save changes to a.ts?` asks; Cancel keeps the tab; Discard closes it with the file unchanged; with it the last tab, the board shows and its row leaves the sidebar.
- **AC6 – External change:** Given `a.ts` open and clean, when another process writes `changed` into it, then the tab shows `changed` within 4 s with no bar. Given it dirty, the bar `a.ts changed on disk` shows; Keep mine then Mod+S writes the tab's text; Reload shows the disk text and clears the dot. A save after an outside write with no check yet writes nothing and shows the bar.
- **AC7 – Markdown:** Given `README.md` with `# Title`, a table, `- [x] done`, a fenced `ts` block, `<b>raw</b>`, a link `https://example.com`, a link `./docs/b.md` and an image `./img.png`, when it opens, then Preview shows an `h1` `Title`, a `table`, a checked disabled checkbox, highlighted code, the text `<b>raw</b>` (no `b` element), the image drawn; clicking the https link calls `shell.openExternal` (stubbed) with it, clicking `./docs/b.md` opens `b.md` in a tab; Edit shows the source, and an edit there shows in Preview after switching back.
- **AC8 – Limits:** Given `pic.png`, `bin.dat` (with a NUL byte) and `big.log` (6 MB), when each is opened, then `pic.png` shows as an `img` with a `data:image/png` source, `bin.dat` shows `Binary file` and `big.log` `Too large to open here (6.0 MB)`, each with Open in <editor> running the fake `code`.
- **AC9 – Drafts:** Given `a.ts` dirty with `draft` typed and another clean tab `b.md`, when the app quits and launches again, then the workspace shows its board with only `a.ts` in the sidebar, dirty; opening it shows `draft`; the file on disk is unchanged; `<userData>/drafts` is 0700 and its file 0600; neither `bikube-state.json` nor the Sync folder's file holds `draft`. Saving deletes the draft file. A draft whose file was changed meanwhile shows the changed-on-disk bar.
- **AC10 – Agent tab and Agent setup:** Given a Claude Code card whose transcript's What changed lists `src/x.ts`, when the user clicks its row, then `x.ts` opens in the editor (no external editor). Given Agent setup listing the fake home's `~/.claude/settings.json`, when the user clicks its Open file, then it opens in a tab with path `~/.claude/settings.json`, and an edit saved with Mod+S is on disk. A path Agent setup didn't list, asked for from the page, is refused and nothing is read.
- **AC11 – Shortcuts and palette:** With the editor view in front, Find opens the search panel inside the editor and typing finds `foo`; Back shows the board; the palette lists `Save file`, `Close tab`, `Toggle wrap`, `Open in VS Code` and `Markdown: Edit` for a Markdown tab, and an open file's row opens it from the board; `board palette list` in a terminal holds none of them.
- **AC12 – Wrap and themes:** Given a 300-character line, when Wrap is turned on, then the line wraps with no horizontal scroll and `"editorWrap": true` is in `bikube-settings.json` across a restart. In Dark, Light and Nord the editor's background equals `--terminal-bg`, tab and header text meet D5's contrast ratios, and at a 320 px wide main area nothing scrolls sideways but the editor's own content.
- **AC13 – Refusals:** a request naming `../outside.txt`, a symlink pointing outside the folder or a folder path reads and writes nothing (Vitest on the core module), and every editor IPC from a card window's frame or a subframe is refused.

## Stack changes

Adds to `native-ui` (described in words, no registry id): **CodeMirror 6** (`@codemirror/*`, `@lezer/highlight`) as the file editor and **markdown-it** as the Markdown renderer. The description becomes "Electron + TypeScript + electron-vite + React + xterm.js (fit, webgl, web-links, search addons) + CodeMirror 6 + markdown-it + node-pty + Vitest + ESLint + electron-builder + npm". Their MIT licences go into `THIRD_PARTY_NOTICES`.

## Data and migrations

- New preference `editorWrap` (boolean, default false) in `bikube-settings.json`, written only when true.
- New `<userData>/drafts/` folder (D11), this machine only, pruned at launch.
- No change to `bikube-state.json` or the Sync folder's file; open tabs are never saved.

## Out of scope

- The editor in card windows, an `Open file…` palette search, creating, renaming or deleting files.
- SSH workspaces (the Files tab and Agent setup already show only a message there).
- Configurable editor shortcuts, next/previous tab shortcuts, split editors, a diff view.
- Remembering clean tabs across a restart (D3).
