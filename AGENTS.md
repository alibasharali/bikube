# AGENTS.md

Drovr: A kanban board for macOS and Linux where every card is a live terminal, for running many coding agents side by side.

Built with Software Factory's workflow: read `docs/agents/workflow.md` before starting on an item, and `docs/agents/stack.md` for the stack picked at creation and its guidelines. Domain terms are in `CONTEXT.md`, decisions in `docs/adr/`.

## Commands

- `npm ci` installs; `postinstall` rebuilds node-pty for Electron (needs python3, make and a C++ compiler on Linux). Where the Electron headers download is blocked (cloud sessions: postinstall fails with a proxy 403), everything else is installed by then: run `npm rebuild node-pty`; the Node build works in Electron too (N-API, ADR 0001). If `node_modules/electron/dist` is empty afterwards (the failed postinstall can skip Electron's own download), run `node node_modules/electron/install.js`.
- `npm run dev` starts the app with hot reload; `npm start` previews the production build.
- `.claude/check.sh` runs everything that must be green: typecheck, lint, Vitest, build, `node .factory/check-stack.mjs`. CI's `check` job runs it. Run as root (cloud sessions), the updater tests that make a folder read-only (`chmod 0555`) fail, since root writes it anyway: Vitest's "keeps the old app when its folder can't be written" and the smoke test "an install that can't swap the app". That is the sandbox, not the change; CI runs as a normal user.
- Individually: `npm run typecheck`, `npm run lint`, `npm test` (Vitest), `npm run build`, `npm run format`.

- `npm run test:packaged` packs the Linux app (`npm run pack`), then runs `e2e/packaged.spec.ts` (`playwright.packaged.config.ts`; not part of `test:smoke`) against `dist/linux-unpacked`: `resources/bin/board` is executable, `resources/bin/claude-settings.json` and `claude-instruction.txt` are there, `resources/THIRD_PARTY_NOTICES` is there, and `resources/app.asar.unpacked/out/main/board-cli.js` exists, then one launch of the packaged `drovr` executable (through `launchApp`'s `executablePath`) that creates a workspace and a card and runs `board status . packaged` in it. Linux only (skipped elsewhere). Needs a display: `xvfb-run -a npm run test:packaged`. CI's `check` job runs it after the smoke tests.
- `npm run benchmark` builds, then runs the 10-terminal performance benchmark (`e2e/benchmark.spec.ts`, `playwright.benchmark.config.ts`): 10 cards in one workspace, all streaming, one open at full size; writes `test-results/benchmark-<profile>.md`. Needs a display: `xvfb-run -a npm run benchmark`; `BENCH_PROFILE=firehose` for the stress profile (unthrottled `yes | cat -n`). The default `sustained` profile asserts the full D8 budget (#1); firehose asserts zero dropped echoes, every session producing output with its status line live, and main event-loop lag p99 within 100 ms, and reports renderer fps and echo max as info (#16 D7). Both tables show the most characters any session had unacknowledged in main (flow control, #16), read from a reader main puts on `globalThis` only when `DROVR_BENCH` is set.
- `npm run dist` builds the release packages for the OS it runs on: the .dmg on macOS (signed ad hoc, not notarized: `identity: '-'` seals the whole bundle; with signing skipped a downloaded copy reads "damaged" with no Open Anyway), `drovr-<version>-x86_64.AppImage` and `drovr-<version>-amd64.deb` on Linux (in `dist/`); `npm run pack` builds an unpacked app for the current OS. In cloud sessions both fail at electron-builder's node-pty rebuild (the same proxy 403 as postinstall), and the failed rebuild deletes node-pty's build, breaking Vitest and any package built after it: run `npm run build && npx electron-builder -c.npmRebuild=false` (add `--dir` for the unpacked app) instead, and `npm rebuild node-pty` if it was already wiped.
- CI also runs `actionlint` (via `check.sh`; install with `go install github.com/rhysd/actionlint/cmd/actionlint@v1.7.7`). `.github/workflows/release.yml` runs two independent jobs on a published release (pre-releases too), each building with the tag's version (`v1.2.3` → `npm version 1.2.3`, or `v1.2.3-rc.1` for a pre-release, which the updater never offers but updates from; any other tag fails): `dmg` on macOS attaches `dist/*.dmg` and the updater's `dist/*-mac.zip` (`drovr-<version>-arm64-mac.zip`), `linux` on Ubuntu attaches `dist/*.AppImage` and `dist/*.deb`; one failing doesn't cancel the other. To release, publish a GitHub release tagged `v<x.y.z>`, higher than the last; `package.json` keeps `0.0.1`.
- Locally, a failed electron-builder node-pty rebuild deletes node-pty's own build (`npm run dist`/`pack` and a bare `electron-builder`): pass `-c.npmRebuild=false` to try a package. node-pty then loads its bundled `prebuilds/<os>-<arch>` module.
- Headless launch: `xvfb-run -a npx electron . --no-sandbox` (after `npm run build`).

## Architecture

- `src/main` Electron main process; `src/preload` the only bridge to the renderer, typed by `src/shared/api.ts` (`window.drovr`); `src/renderer` React UI; `src/core` plain TS with no Electron imports (session/PTY logic), unit-tested with Vitest on Linux.
- `board` (#9): inside a card's terminal (only there), an agent runs `board move <card> <column>`, `board status <card> <text>`, `board activity <card> working|waiting|question|none` (#31: a pill on the card, runtime only, cleared on stop and start) or `board session <card> <uuid>` (run by Claude Code's hooks: the conversation the card resumes, saved) (`.` is the calling card; `board help`). `resources/bin/board` (a POSIX sh wrapper; its directory is prepended to PATH in the environment of every card's shell and given as `DROVR_BIN`, so `"$DROVR_BIN/board"` works whatever a profile does to PATH) runs `out/main/board-cli.js` (built from `src/main/board-cli.ts`) with Drovr's own executable as Node; it talks to main over `<userData>/board/board.sock` (a private 0700 directory, the socket 0600), and main forwards each request to the renderer, which applies it to the store. Packaged, `bin/` is in `extraResources` and the CLI module and its chunks are unpacked from the asar (`electron-builder.yml`); after `npm run pack`, `dist/linux-unpacked/resources/bin/board` must be executable and `resources/app.asar.unpacked/out/main/board-cli.js` must exist. In SSH cards (#25) the local shell running `ssh` gets none of this: before each SSH session (main pane or extra pane) main listens on its own `<userData>/board/s-<16 hex>.sock`, serving only that card (`src/core/session-sockets.ts`), and the line becomes `ssh -o ExitOnForwardFailure=no -R /tmp/drovr-<32 hex>.sock:<that socket> -t -- …` (`src/core/ssh-command.ts`); the remote command writes a POSIX sh `board` script running an embedded perl or python3 client (`src/core/remote-board.ts`, no backslashes so it stays fish-safe) into a private `mktemp -d` directory and removes it and the remote socket when the shell ends. Claude Code cards (#31 D14) start `claude --settings "$DROVR_CLAUDE_SETTINGS"`: every card's shell gets `DROVR_CLAUDE_SETTINGS`, locally `resources/bin/claude-settings.json` (hooks calling `board activity`, and a SessionStart hook printing `claude-instruction.txt`); both files are generated from `src/core/claude-hooks.ts` and a test keeps them equal; the SSH remote command writes copies beside the remote `board` (the JSON's backslashes printed by `awk`, so the command keeps none). Session sockets close when their session exits and on quit; leftovers are removed at launch. Without a local socket ssh gets no `-R`, and the card runs anyway.
- Terminal themes: `src/core/ghostty-themes.json` is Ghostty's 463 theme files (iTerm2-Color-Schemes), rebuilt with `node scripts/import-ghostty-themes.mjs <ghostty>/themes`; "Use Ghostty theme" reads the user's Ghostty config in main (`src/core/ghostty-config.ts`). The bundled `Symbols Nerd Font Mono` (`src/renderer/src/assets/fonts`) is loaded before the first render and appended to every terminal's font family. Their licences are in `THIRD_PARTY_NOTICES` (packaged by `electron-builder.yml`'s `extraResources`): update it when either changes.
- Terminal and agent preferences (`Preferences` in `src/core/settings.ts`: cursor, scrollback, line height, letter spacing, bell, copy on select, Option as Meta, bold bright, notifications, Claude Code status) are one table of defaults and checks; each is written to `drovr-settings.json` only when it differs from its default. Notifications (`src/renderer/src/attention.ts`) watch every card's activity through `CardSessions.onActivity`; main sets the Dock badge, focuses the window and asks for attention (`src/main/attention.ts`). The Claude Code status switch reaches the session start hook as `DROVR_CLAUDE_STATUS` (local env, or exported by the SSH remote command).
- Worktree cards: main runs `git` and `cp` with `execFile` (no shell) through `src/core/worktrees.ts`, whose commands are injected so `worktrees.test.ts` drives real throwaway repositories; worktrees live in `<userData>/worktrees`, and main only checks or removes paths inside it (`src/main/worktrees.ts`). Branch names come from `src/core/worktree-names.ts`. Name test fixtures for ignored files something like `local.conf`: the secrets hook blocks any command that touches dotenv files.
- Branch menu (#33): the title bar's branch chip opens it (`src/renderer/src/BranchMenu.tsx`), acting on the open worktree card's directory, else the workspace folder; local workspaces only. `src/core/git.ts` lists and switches branches with git injected (`GitRunner`), every command with the no-prompt environment (`gitEnv`: `GIT_TERMINAL_PROMPT=0`, no askpass, ssh in batch mode, the user's `GIT_SSH_COMMAND`, `core.sshCommand` or `GIT_SSH` kept), a 2-minute timeout and stdin closed, and `gitError` turning stderr into the menu's error line; `git.test.ts` drives real throwaway repositories with a local bare remote. Main (`src/main/git.ts`, main frame only) runs it with `execFile` in an absolute existing folder, and only on branch names git itself lists.
- Updates (`src/core/updates.ts`, `src/main/updates.ts`, the sidebar's `UpdateButton`): main checks GitHub's `releases/latest` (full releases only) at launch and every 4 h, and on macOS (Apple silicon) and in an AppImage downloads this platform's file into `<userData>/updates`, checks its size and the SHA-256 GitHub publishes, and unzips the `.app` with `ditto`. Install and Relaunch (or quitting) starts a detached POSIX sh script (`INSTALL_SCRIPT`) that waits for main's pid to end, swaps the app (`installPaths`: on macOS the bundle's `Contents`, so only `Drovr.app` must be writable and a standard account can update in `/Applications`; an AppImage in its folder; the old one back on failure, the reason in `<userData>/update-install-failed` for the next launch) and opens it again. No code signing: Squirrel.Mac would need it. Every URL must be under this repository's releases. A skipped version is kept in `<userData>/drovr-update.json`. A release whose file isn't up yet (missing, still uploading or without its digest: the release workflow takes about 10 minutes) reads Not Ready Yet and is checked again every 2 minutes, up to 30 times per version (`WaitingRechecks`; a check the user asks for starts them again), and the popup only promises a recheck that will come. The development build checks nothing unless `DROVR_UPDATE_FEED` (with `DROVR_UPDATE_CURRENT`, `DROVR_UPDATE_TARGET`, `DROVR_UPDATE_WAITING_MS` and `DROVR_UPDATE_WAITING_CHECKS`) is set, which only it honours: `e2e/updates.spec.ts` serves a local feed and swaps a fake app, never Drovr.
- Window settings: contextIsolation on, nodeIntegration off, sandbox on. Don't weaken them.
- Terminal flow control (#16): main pauses a PTY above 100k characters the renderer hasn't acknowledged (`terminal:ack`, sent once xterm has parsed them) and resumes below 5k (`src/core/flow-control.ts`). Every chunk the renderer receives must be acknowledged exactly once (`SessionRouter` + `AckBatcher`), or its shell stays paused. node-pty drops a paused PTY's unread output 200 ms after its shell exits, so `SessionManager` resumes before kill and resumes a paused session whose shell is gone.
- Sync folder I/O (#26): never block main on the sync folder (it may be a stalled network mount or a cloud placeholder). `SyncFolder` uses async fs and runs every operation one at a time on its own queue, so a new operation must go through that queue to keep #13 D4 (no echo) and D12 (never overwrite). A libuv thread stuck in a stalled fs call keeps the process from exiting, so quit SIGKILLs main when sync is still busy at `quit` (`src/core/quit-hold.ts`).
- No macOS-only APIs outside packaging and window chrome (Linux and Windows builds stay possible). node-pty's `kill(signal)` throws on Windows: pass a signal only off `win32` (#18).
- Stack and decisions: `docs/adr/0001-stack.md`. Never deploy by hand; releases come from a GitHub release workflow.

This file is for every coding agent; `CLAUDE.md` imports it.
