# Context

The domain language of Bikube. One entry per term: what it means here, and what it doesn't.

<!-- - **Term**: definition. Not to be confused with … -->

- **Card**: a task on the board, worked by an agent: its startup command is always an agent (`Claude Code`, a preset, or `Custom`), never a plain shell; its column is where the task stands (Backlog, In Progress, Review, Done for a new workspace), and its status (Running, Stopped…) is its process's, shown on the card. Not a shell: plain terminals are the workspace's shells.
- **Card description**: a card's optional task, plain markdown text of at most 100,000 characters, entered in the **New card** dialog, changed with **Edit description…** (its ⋯ menu, or the palette for the open card) or by an agent with `board describe`, and read with `board description`; saved and synced like the title, shown and edited as text (never rendered), and marked on the board card by a document icon whose tooltip is its first lines. On every fresh agent start of the card (its first, a newly picked agent, a new worktree session) the agent gets one fixed prompt telling it to read the description and ask the user whether to start on it; never on a resume. Not the agent status, which the agent sets about its progress, nor a message typed into a running agent.
- **New mark**: the `New` pill on a card that `board create` made from a card in another workspace, until the card's first open on any machine clears it (saved and synced). Cards made in the calling workspace, by hand or by a restart get none. Not a notification, and not waiting.
- **View**: how a workspace shows its cards: **Default** (new workspaces, and those from before views), following Settings' **Default view** on each machine, or its own (synced with the workspace): **Kanban**, its columns as lanes, or **Grid**, every card in one grid, latest first (by when it was created, on any machine, or last opened on this one), in sections: **Needs you** (running cards waiting for the user), **Running**, and **Stopped** (which folds), with a search (title, branch, agent) and a filter. Cards keep their columns in both: switching changes no card, `board move` still moves them (automatic moves wait while a workspace shows Grid), and a card made in the grid goes to the bottom of the first column. The grid offers no moves between columns. A Kanban workspace shows each column in **Manual order** (the default: the stored board order) or **Recently opened first** (the grid's latest-first rule, cards with no time last in board order), set from any column's ⋯ menu or the Edit dialog for the whole board and synced; it never changes the stored order: while sorted, a card dropped into another column goes to that column's bottom, a drop within a column and Alt+Up/Down do nothing, and the Card display limit folds the sorted order. The first launch asks for the Default view (only while there is no workspace). Not to be confused with a card's full-size view.
- **Shell**: a terminal of a workspace that isn't a task, listed in the side panel's **Shells** tab, not on its board. Every workspace has the **Default shell** (a plain shell in its folder, not stored); named shells add an optional one-line command typed each time they start (a test watcher) and can start when the workspace is first opened in a run of the app. A **trigger** is a named shell whose click runs its command in the background (a build, a dev server): it exits when the command ends, done or failed by its exit code, and a click while it runs opens it; until then it is out of the sidebar. A shell opens, splits and stops like a card, in the workspace's folder (over SSH in an SSH workspace), or a named one in a worktree card's worktree it was moved to (**Run in this worktree** in its Start button's dropdown beside that card, or **Run in** in its menu; local workspaces only, back in the folder once that card is gone). Its definition is saved and synced; where it runs and its process stay on each machine. Not to be confused with the Shell setting, which picks the program every card and shell runs. A **temporary shell** (`Terminal N`, the lowest free N) is a plain shell the **New shell** shortcut adds while the Default shell runs (it opens the Default shell otherwise): removed as soon as it stops, never saved or synced, and never edited or moved to a worktree.
- **Startup command**: what Bikube types into a card's login shell, followed by Enter, right after each start: `Claude Code` (`claude` with the card's agent session id and Bikube's Claude settings file, whose hooks set the card's activity, ask Claude to keep a one-line agent status and report the conversation the card is in with `board session`; until a message is sent the id is started fresh, after that resumed), an agent preset (`Codex`, `Gemini CLI`, `OpenCode`, `Pi`: the agent's plain command the first time the card starts it, then its resume command picking the agent's latest session in the card's directory, falling back to the plain command), or `Custom` (a one-line command run as written). Two cards with the same preset in one directory resume the same session. Each card has its own; a workspace's default startup command is only the preset for new cards. Not to be confused with the login shell itself, which every start runs.
- **Agent session id**: a random UUID v4 a card gets at creation and keeps for life, whatever its startup command; Claude Code cards pass it to `claude --session-id` / `--resume` so reopening the card returns to the same conversation; when Claude Code moves to another conversation (`/resume`), its hooks replace it with that one's id. Not the card's id, nor the PTY session id.
- **Stopped**: a card whose shell has exited; its process is gone; its output stays on this machine (unless Keep output is off) and is shown above the next start's output, and opening it starts it again with its startup command. Replaces #4's "Exited (code N)". Not to be confused with `Couldn't start`, where the shell never ran. An SSH card whose `ssh` fails reads `SSH failed` instead.
- **Close**: stopping a running card's process from its menu, the board card's stop button or the Close card shortcut (or Close pane in the card's main pane), after a confirmation unless the user checked its **Don't ask again** (Settings' **Ask before closing a card** turns it back on); the card keeps its place, title, startup command and agent session id and becomes `Stopped`, so opening it again resumes it. Not to be confused with `Delete`, which removes the card, nor with `Back`, which leaves the process running.
- **Saved state**: the board as Bikube keeps it across restarts in `bikube-state.json`: every workspace, its columns and cards in order, their titles, directories, SSH hosts, startup commands and agent session ids, and which workspace is active. With a **Sync folder** set, the same board (without the active workspace) is also kept there for other machines. Not terminal processes, screens or scrollback: after a restart every card is `Stopped` until it is opened. Not to be confused with UI preferences such as window size or the collapsed sidebar, which are not saved, nor with card windows, which a restart never reopens.
- **Kept output**: a card's main pane output, with its colours, saved on this machine whenever its shell stops (it exits, is Closed or `SSH failed`) and when the app quits, up to the Scrollback setting's lines and 1,000,000 characters; when the card starts again it is shown above a dim `── Previous output · <time> ──` line, read-only, with the new session below, and the next save includes it, so history accumulates. Removed when the card is deleted, at launch for cards no longer on the board, and all of it when **Keep output after a card stops** is turned off in Settings (on by default). Never an extra pane, the Default shell or a named shell; not terminal modes, a full-screen app's screen or the process. Not saved state: kept in its own folder, never in `bikube-state.json` and never synced.
- **Board command**: `board`, the command every card's shell has on its PATH, through which a program in the card reads and changes the board and tells it what it is doing: `board workspaces` lists every workspace, `board list` a workspace's columns and cards, `board create [--agent <agent>] [--description-file <file>|-] [--worktree [--branch <name>]] <column> <title>` adds a card (not started; with a **Pending worktree** for `--worktree`), `board rename <card> <title>` renames one, `board description <card>` prints its **Card description** and `board describe <card> <file>|-` replaces it, `board move <card> <column>` moves a card to the bottom of a column of its own workspace (never to another workspace), `board status <card> <text>` sets its agent status, `board activity <card> working|waiting|question|none` sets or clears its activity, `board session <card> <id>` sets the Claude Code conversation the card resumes (its hooks run it). `board usage <card> <transcript>` reports a Claude Code card's **Usage** read from its transcript (its hooks run it; not in `board help`). `.` is the calling card, and a card's id names a card in any workspace, while card and column titles resolve in the calling workspace or in the one `--workspace <name or id>` names (on `list`, `create`, `rename`, `move`, `status`, `description` and `describe`). It reaches the running app over a socket only the same user can use, and works only from a card with a running shell. In an SSH card it is a small script Bikube writes on the host for that session, reaching the app over a socket the user's own `ssh` forwards (`-R`), which serves only that card; it takes only its own card's commands (`description` included; no `workspaces`, `create`, `rename`, `describe`, `--workspace` or another card), it needs `perl` or `python3` on the host, and when the host refuses the forward it says it can't reach Bikube while the card runs on. Not a global install: outside a Bikube card it isn't on the PATH, and nothing of it stays on the host after the session.
- **Activity**: what the agent in a card says it is doing, set with `board activity`: `working`, `waiting` (for the user) or `question` (it needs the user's answer); `none` clears it. Shown as a small coloured pill on the card's status row while the card is `Running`: `Working`, `Waiting for you` or `Needs your answer`. Like the agent status it is cleared when the card's process stops or starts again, and never saved or synced. A card or shell whose activity is `Waiting for you` or `Needs your answer` is **waiting**: each workspace's row in the sidebar counts its waiting cards and shells, and the **Next waiting card** shortcut (Cmd+J on macOS, Ctrl+Shift+J elsewhere) opens the one that has waited longest, in whatever workspace, then the next on each press. Separate from the agent status, which is free text.
- **Usage**: the Claude Code conversation of a local card in tokens and context, reported by Bikube's hooks with `board usage`. Shown as a context bar on the board card; no cost is estimated. Runtime only: kept across a stop, gone when the card is deleted, its conversation is cleared (`/clear`) or the app quits, never saved or synced. Not for SSH cards or other agents.
- **Automatic moves**: a workspace's up to three rules, set in its Edit dialog under **Move cards automatically**, each naming one of its columns: **When working** (a card's activity becomes `working`), **When waiting for you** (it becomes `waiting` or `question`) and **When stopped** (the card's shell exits or is Closed while the app runs; not `Couldn't start`, `SSH failed`, a delete, a quit or a restart). A rule fires only on a change, moving the card to the bottom of its column as `board move` does; a card moved by hand stays until the next change. Every rule is off by default; they apply to every card of the workspace, never to its shells, and only on the instance running the card, the move itself saved and synced like any other. A workspace shown as Grid has no columns in view, so its Edit dialog hides the rules and none runs; they are kept for when it shows Kanban again.
- **Agent status**: a short text a program in a card sets with `board status`, shown on its own line under the card's status row while the card is `Running` (up to 2 lines, full text in its tooltip), above the last output line; empty text clears it. It is cleared when the card's process stops or starts again, and never saved. Not to be confused with the card's status (`Running`, `Stopped`, `SSH failed`, `Couldn't start`), which Bikube derives itself.
- **Settings**: the app-wide preferences Bikube keeps across restarts in `bikube-settings.json`, the same for every workspace and card: the colour theme (`System`, `Dark` or `Light`), the **App theme** (Default, Bikube, Catppuccin, Rosé Pine, Nord or Gruvbox: the palette of the app's chrome, each with a dark and a light version the colour theme picks between; not to be confused with the colour theme, which only picks dark or light, nor with the terminal theme, which it never changes), the terminals' font size and family, the **Shell** new local cards and panes start (the login shell by default), a **terminal theme** for each appearance (the palette of the terminals, picked from Ghostty's themes, or the colours of the user's own Ghostty config with `Use Ghostty theme`; not to be confused with the colour theme, which colours the app itself), the keyboard shortcuts the user changed (Back, Split right, Split down, Close pane, Close card, Settings, Toggle panel, Find, Command palette, Next waiting card, Previous prompt, Next prompt), the **global shortcut** that shows or hides Bikube from any app (none by default) and whether it opens the next waiting card, and, the first UI preferences that are saved, whether the **side panel** beside an open card or shell, or beside a workspace's board (#57), shows and its width (one value for the board and every card and shell), the **Editor** the side panel's Files tab opens a file with (VS Code by default, Cursor, Zed, the system default app, or a custom command run by the user's shell), and whether **Inline images** (sixel and iTerm2 images printed in a terminal) show, on by default and read when a terminal is created, so turning it off leaves open terminals as they are. The same file keeps this machine's **Sync folder**, which is never synced. Not saved state: the board's file is separate and never holds them. Not to be confused with the other UI preferences such as window size or the collapsed sidebar, which are not saved at all.
- **Worktree card**: a card created with **Own worktree** in a local workspace that is a git repository: Bikube makes a git worktree for it on a new branch (`bikube/<title slug>`, editable when creating it) from the repository's current HEAD, copies the repository's git-ignored files into it (copy-on-write where the file system allows), and the card runs there, so its agent's changes never touch the workspace's own checkout or another card's. Its worktrees live in Bikube's data folder (`worktrees/<repo>-<id>/<folder>`). Deleting the card asks whether to remove its worktree too, warning about uncommitted changes; its branch is always kept. Deleting a workspace keeps its cards' worktrees. Its workspace's **Worktree setup** (when not empty) runs first in its terminal, once: on every start until it succeeds (or is skipped), then never again. Not a workspace: it shares its workspace's board and repository.
- **Pending worktree**: a worktree `board create --worktree` asked for, checked at create (a local workspace in a git repository, a new valid branch) but not made yet: the card shows `Worktree on first open` and runs nothing until its first open on any machine, which makes it as **Move to own worktree…** does (the card then becomes a worktree card, with the workspace's Worktree setup queued and a new agent session) before it starts; if git fails, the card stays pending and its view offers **Retry** and **Run in workspace folder** (which drops it). Saved and synced, so only the machine that opens it first touches git. Not a worktree card until it is made.
- **Update**: a newer full release of Bikube on GitHub, offered by the **Update Available** button above Settings. On macOS (Apple silicon) and in an AppImage Bikube downloads and checks it itself, and **Install and Relaunch** (or the next quit, after **Later**) replaces the app it runs from (on macOS, the inside of its own `Bikube.app`, so a standard account needs no administrator); **Skip** ignores that version until a newer one. Elsewhere (the .deb, a folder Bikube can't write) it links to the release. Installing stops every running terminal, like quitting. Not a sync, and not a card's agent updating itself.
- **Pane**: one terminal inside a card's full-size view, which shows 1 to 4 side by side or stacked. The **main pane** is the card's own terminal: its startup command, agent session id and status, the one the board shows. Every other pane is an **extra pane**: a plain login shell with no startup command, in the directory the focused pane's shell last reported (shell integration) when that is a local directory that still exists, else in the card's directory, which can run `board` for the card (in an SSH card, its own `ssh` session to the card's host and directory, with its own forwarded `board` socket). Extra panes live and die with the main pane: when it stops, or the card is deleted, they are killed and discarded. Not saved state: after a restart a card has only its main pane. Not a card: an extra pane has no title, status or place on the board.
- **SSH workspace**: a workspace whose cards run on another machine: it has a **host**, a destination exactly as `ssh` takes it (`me@devbox`, an alias from `~/.ssh/config`), and its working directory is a path on that host (absolute or starting with `~`), never checked from the dialog. Each card's terminal runs the user's own `ssh` to the host from the local login shell, `cd`s into the remote directory and runs the startup command there; every extra pane opens its own `ssh` session. A card copies the host with the directory at creation and keeps both for life, so editing the workspace changes new cards only. A workspace without a host is local. Remote cards have `board` like local ones, through a socket each `ssh` session forwards, if the host has `perl` or `python3`. Not a sync: the board, its saved state and settings stay on this Mac, and nothing is copied to or from the host beyond each session's `board` script and, for Claude Code, its settings file and instruction, removed when it ends.
- **SSH failed**: the status of an SSH card whose `ssh` exited by itself with code 255 (host unreachable, authentication failed, connection dropped, remote directory missing): `SSH failed: <last output line>`. Otherwise it is like `Stopped` (screen gone, opening it connects again), and after a restart it is `Stopped`; an extra pane whose `ssh` fails keeps its screen with `SSH failed` below it until closed. Not `Stopped`, which is any other exit or a stop by Close, delete or reload; not `Couldn't start`, where Bikube never ran the shell at all.
- **Sync folder**: a folder the user picks in Settings, which their own file sync tool (iCloud Drive, Dropbox, Syncthing…) carries between machines; Bikube reads and writes one file in it, `bikube-board.json`, holding the board: every workspace, column and card, with local directories under the home directory written as `~`. Turning it on joins the folder's board with this machine's; after that the last machine to change the board wins, and a change reaches the other open machines live (read at launch, when the folder changes and on window focus). A sync never stops or removes a card running on this machine: it stays, and is written back. When the folder is missing the sidebar shows `Sync folder unavailable` and changes stay on this machine until it is back; when the file can't be read (`Sync file unreadable`) Bikube leaves it alone and never overwrites it. Kept per machine (in `bikube-settings.json`), never synced itself. Not a Bikube server or network sync, and not the saved state: settings, the active workspace, processes, scrollback (kept output too: it is never synced), panes and agent status stay on each machine, and a synced card is `Stopped` on a machine until opened there.
- **Dev server chip**: a small `localhost:<port>` chip under a running local card's status lines (a workspace shell's under its row in the Shells tab) for each dev server URL any of its panes showed in the current start (an http or https URL on `localhost`, `127.0.0.1`, `0.0.0.0` or `[::1]` with a port), whether a program printed it or the user typed or recalled it, shown only while something listens on that port on this machine; clicking it opens the URL in the default browser, never the card. At most three show, then `+N`. Forgotten when the shell exits, is Closed or restarted, or the card is deleted; never saved or synced. Not for SSH cards, whose `localhost` is the remote host, and not a preview: nothing is embedded in Bikube.
- **Command palette**: a dialog opened anywhere in the window with its shortcut (Cmd+K on macOS, Ctrl+Shift+P elsewhere, changeable in Settings) that fuzzy-finds every card and shell of every workspace by title, workspace, worktree branch, status and activity, and opens the picked one at full size in its workspace (switching to it and starting it as a click would), and lists the app's existing actions that would do something now (the open card's Back, splits, Close card, Find, moves; New card, Next waiting card, themes, Settings, switching workspace…) with their shortcuts. Not a search of terminal output or files, and not a new way to act: every action is one the app already has. It keeps no query or history across opens or restarts.
- **Shell integration**: the marks a shell sends around each prompt and command (OSC 133, VS Code's OSC 633) and the directory it reports (OSC 7), from which a terminal knows its **commands**: each from the start of its output to its end, on its command line's row, with an exit code. A **failed command** is one that ended with an exit code other than 0; its line gets a red bar and a `✗ <code>` badge. A **long command**, one that ran 10 seconds or more, sends a notification when it ends in a pane the user isn't looking at (`Command finished` or `Command failed (exit <code>)`), when Notifications are on; it is not waiting and changes no activity. A new split of a local card starts in the reported directory; the card's own directory never changes. Runtime only: kept with the terminal's screen and gone with it, never saved or synced. Not an agent's activity, which only `board activity` sets.
- **Card window**: a second window showing one card or workspace shell at full size, opened with **Open in new window** (its ⋯ menu, a shell's menu, the open card's shortcut or the command palette) so two agents can be watched at once; titled `<title> · <workspace>`, with only the card view (panes, zoom, Find, side panel, Close confirmation), no sidebar, board, title bar chips, palette or Settings. The card keeps running exactly as on its board, which shows it `Running` with an `In window` chip; opening it again from anywhere brings its window forward. Closing the window (or Back there) puts the card back on its board, still running; its shell stopping, its deletion or the main window closing or reloading closes it. The user is looking at a card while its window is focused, so it notifies nothing then. Runtime only: never saved, never reopened after a restart. Not a second board or app instance (a workspace's board never opens in a window), and not a pane.
