# Context

The domain language of Drovr. One entry per term: what it means here, and what it doesn't.

<!-- - **Term**: definition. Not to be confused with … -->

- **Card**: a task on the board, worked by an agent: its startup command is always an agent (`Claude Code`, a preset, or `Custom`), never a plain shell; its column is where the task stands (Backlog, In Progress, Review, Done for a new workspace), and its status (Running, Stopped…) is its process's, shown on the card. Not a shell: plain terminals are the workspace's shells.
- **Shell**: a terminal of a workspace that isn't a task, shown in the strip above its board, not on it. Every workspace has the **Default shell** (a plain shell in its folder, not stored); named shells add an optional one-line command typed each time they start (a dev server, a test watcher) and can start when the workspace is first opened in a run of the app. A shell opens, splits and stops like a card, in the workspace's folder (over SSH in an SSH workspace); never a worktree. Its definition is saved and synced; its process stays on each machine. Not to be confused with the Shell setting, which picks the program every card and shell runs.
- **Startup command**: what Drovr types into a card's login shell, followed by Enter, right after each start: `Claude Code` (`claude` with the card's agent session id and Drovr's Claude settings file, whose hooks set the card's activity, ask Claude to keep a one-line agent status and report the conversation the card is in with `board session`; until a message is sent the id is started fresh, after that resumed), an agent preset (`Codex`, `Gemini CLI`, `OpenCode`: the agent's plain command the first time the card starts it, then its resume command picking the agent's latest session in the card's directory, falling back to the plain command), or `Custom` (a one-line command run as written). Two cards with the same preset in one directory resume the same session. Each card has its own; a workspace's default startup command is only the preset for new cards. Not to be confused with the login shell itself, which every start runs.
- **Agent session id**: a random UUID v4 a card gets at creation and keeps for life, whatever its startup command; Claude Code cards pass it to `claude --session-id` / `--resume` so reopening the card returns to the same conversation; when Claude Code moves to another conversation (`/resume`), its hooks replace it with that one's id. Not the card's id, nor the PTY session id.
- **Stopped**: a card whose shell has exited; its process is gone; its output stays on this machine (unless Keep output is off) and is shown above the next start's output, and opening it starts it again with its startup command. Replaces #4's "Exited (code N)". Not to be confused with `Couldn't start`, where the shell never ran. An SSH card whose `ssh` fails reads `SSH failed` instead.
- **Close**: stopping a running card's process from its menu, the board card's stop button or the Close card shortcut (or Close pane in the card's main pane), after a confirmation; the card keeps its place, title, startup command and agent session id and becomes `Stopped`, so opening it again resumes it. Not to be confused with `Delete`, which removes the card, nor with `Back`, which leaves the process running.
- **Saved state**: the board as Drovr keeps it across restarts in `drovr-state.json`: every workspace, its columns and cards in order, their titles, directories, SSH hosts, startup commands and agent session ids, and which workspace is active. With a **Sync folder** set, the same board (without the active workspace) is also kept there for other machines. Not terminal processes, screens or scrollback: after a restart every card is `Stopped` until it is opened. Not to be confused with UI preferences such as window size or the collapsed sidebar, which are not saved.
- **Kept output**: a card's main pane output, with its colours, saved on this machine whenever its shell stops (it exits, is Closed or `SSH failed`) and when the app quits, up to the Scrollback setting's lines and 1,000,000 characters; when the card starts again it is shown above a dim `── Previous output · <time> ──` line, read-only, with the new session below, and the next save includes it, so history accumulates. Removed when the card is deleted, at launch for cards no longer on the board, and all of it when **Keep output after a card stops** is turned off in Settings (on by default). Never an extra pane, the Default shell or a named shell; not terminal modes, a full-screen app's screen or the process. Not saved state: kept in its own folder, never in `drovr-state.json` and never synced.
- **Board command**: `board`, the command every card's shell has on its PATH, through which a program in the card tells the board what it is doing: `board move <card> <column>` moves a card of the same workspace (`.` is the calling card) to the bottom of a column, `board status <card> <text>` sets its agent status, `board activity <card> working|waiting|question|none` sets or clears its activity, `board session <card> <id>` sets the Claude Code conversation the card resumes (its hooks run it). It reaches the running app over a socket only the same user can use, and works only from a card with a running shell. In an SSH card it is a small script Drovr writes on the host for that session, reaching the app over a socket the user's own `ssh` forwards (`-R`), which serves only that card; it needs `perl` or `python3` on the host, and when the host refuses the forward it says it can't reach Drovr while the card runs on. Not a global install: outside a Drovr card it isn't on the PATH, and nothing of it stays on the host after the session.
- **Activity**: what the agent in a card says it is doing, set with `board activity`: `working`, `waiting` (for the user) or `question` (it needs the user's answer); `none` clears it. Shown as a small coloured pill on the card's status row while the card is `Running`: `Working`, `Waiting for you` or `Needs your answer`. Like the agent status it is cleared when the card's process stops or starts again, and never saved or synced. A card or shell whose activity is `Waiting for you` or `Needs your answer` is **waiting**: each workspace's row in the sidebar counts its waiting cards and shells, and the **Next waiting card** shortcut (Cmd+J on macOS, Ctrl+Shift+J elsewhere) opens the one that has waited longest, in whatever workspace, then the next on each press. Separate from the agent status, which is free text.
- **Automatic moves**: a workspace's up to three rules, set in its Edit dialog under **Move cards automatically**, each naming one of its columns: **When working** (a card's activity becomes `working`), **When waiting for you** (it becomes `waiting` or `question`) and **When stopped** (the card's shell exits or is Closed while the app runs; not `Couldn't start`, `SSH failed`, a delete, a quit or a restart). A rule fires only on a change, moving the card to the bottom of its column as `board move` does; a card moved by hand stays until the next change. Every rule is off by default; they apply to every card of the workspace, never to its shells, and only on the instance running the card, the move itself saved and synced like any other.
- **Agent status**: a short text a program in a card sets with `board status`, shown on its own line under the card's status row while the card is `Running` (up to 2 lines, full text in its tooltip), above the last output line; empty text clears it. It is cleared when the card's process stops or starts again, and never saved. Not to be confused with the card's status (`Running`, `Stopped`, `SSH failed`, `Couldn't start`), which Drovr derives itself.
- **Settings**: the app-wide preferences Drovr keeps across restarts in `drovr-settings.json`, the same for every workspace and card: the colour theme (`System`, `Dark` or `Light`), the terminals' font size and family, the **Shell** new local cards and panes start (the login shell by default), a **terminal theme** for each appearance (the palette of the terminals, picked from Ghostty's themes, or the colours of the user's own Ghostty config with `Use Ghostty theme`; not to be confused with the colour theme, which colours the app itself), the keyboard shortcuts the user changed (Back, Split right, Split down, Close pane, Close card, Settings, Toggle panel, Find, Command palette, Next waiting card, Previous prompt, Next prompt), and, the first UI preferences that are saved, whether the **side panel** beside an open card or shell, or beside a workspace's board (#57), shows and its width (one value for the board and every card and shell), and the **Editor** the side panel's Files tab opens a file with (VS Code by default, Cursor, Zed, the system default app, or a custom command run by the user's shell). The same file keeps this machine's **Sync folder**, which is never synced. Not saved state: the board's file is separate and never holds them. Not to be confused with the other UI preferences such as window size or the collapsed sidebar, which are not saved at all.
- **Worktree card**: a card created with **Own worktree** in a local workspace that is a git repository: Drovr makes a git worktree for it on a new branch (`drovr/<title slug>`, editable when creating it) from the repository's current HEAD, copies the repository's git-ignored files into it (copy-on-write where the file system allows), and the card runs there, so its agent's changes never touch the workspace's own checkout or another card's. Its worktrees live in Drovr's data folder (`worktrees/<repo>-<id>/<folder>`). Deleting the card asks whether to remove its worktree too, warning about uncommitted changes; its branch is always kept. Deleting a workspace keeps its cards' worktrees. Its workspace's **Worktree setup** (when not empty) runs first in its terminal, once: on every start until it succeeds (or is skipped), then never again. Not a workspace: it shares its workspace's board and repository.
- **Update**: a newer full release of Drovr on GitHub, offered by the **Update Available** button above Settings. On macOS (Apple silicon) and in an AppImage Drovr downloads and checks it itself, and **Install and Relaunch** (or the next quit, after **Later**) replaces the app it runs from (on macOS, the inside of its own `Drovr.app`, so a standard account needs no administrator); **Skip** ignores that version until a newer one. Elsewhere (the .deb, a folder Drovr can't write) it links to the release. Installing stops every running terminal, like quitting. Not a sync, and not a card's agent updating itself.
- **Pane**: one terminal inside a card's full-size view, which shows 1 to 4 side by side or stacked. The **main pane** is the card's own terminal: its startup command, agent session id and status, the one the board shows. Every other pane is an **extra pane**: a plain login shell with no startup command, in the directory the focused pane's shell last reported (shell integration) when that is a local directory that still exists, else in the card's directory, which can run `board` for the card (in an SSH card, its own `ssh` session to the card's host and directory, with its own forwarded `board` socket). Extra panes live and die with the main pane: when it stops, or the card is deleted, they are killed and discarded. Not saved state: after a restart a card has only its main pane. Not a card: an extra pane has no title, status or place on the board.
- **SSH workspace**: a workspace whose cards run on another machine: it has a **host**, a destination exactly as `ssh` takes it (`me@devbox`, an alias from `~/.ssh/config`), and its working directory is a path on that host (absolute or starting with `~`), never checked from the dialog. Each card's terminal runs the user's own `ssh` to the host from the local login shell, `cd`s into the remote directory and runs the startup command there; every extra pane opens its own `ssh` session. A card copies the host with the directory at creation and keeps both for life, so editing the workspace changes new cards only. A workspace without a host is local. Remote cards have `board` like local ones, through a socket each `ssh` session forwards, if the host has `perl` or `python3`. Not a sync: the board, its saved state and settings stay on this Mac, and nothing is copied to or from the host beyond each session's `board` script and, for Claude Code, its settings file and instruction, removed when it ends.
- **SSH failed**: the status of an SSH card whose `ssh` exited by itself with code 255 (host unreachable, authentication failed, connection dropped, remote directory missing): `SSH failed: <last output line>`. Otherwise it is like `Stopped` (screen gone, opening it connects again), and after a restart it is `Stopped`; an extra pane whose `ssh` fails keeps its screen with `SSH failed` below it until closed. Not `Stopped`, which is any other exit or a stop by Close, delete or reload; not `Couldn't start`, where Drovr never ran the shell at all.
- **Sync folder**: a folder the user picks in Settings, which their own file sync tool (iCloud Drive, Dropbox, Syncthing…) carries between machines; Drovr reads and writes one file in it, `drovr-board.json`, holding the board: every workspace, column and card, with local directories under the home directory written as `~`. Turning it on joins the folder's board with this machine's; after that the last machine to change the board wins, and a change reaches the other open machines live (read at launch, when the folder changes and on window focus). A sync never stops or removes a card running on this machine: it stays, and is written back. When the folder is missing the sidebar shows `Sync folder unavailable` and changes stay on this machine until it is back; when the file can't be read (`Sync file unreadable`) Drovr leaves it alone and never overwrites it. Kept per machine (in `drovr-settings.json`), never synced itself. Not a Drovr server or network sync, and not the saved state: settings, the active workspace, processes, scrollback (kept output too: it is never synced), panes and agent status stay on each machine, and a synced card is `Stopped` on a machine until opened there.
- **Dev server chip**: a small `localhost:<port>` chip under a running local card's status lines (a workspace shell's in the shell strip) for each dev server URL any of its panes showed in the current start (an http or https URL on `localhost`, `127.0.0.1`, `0.0.0.0` or `[::1]` with a port), whether a program printed it or the user typed or recalled it, shown only while something listens on that port on this machine; clicking it opens the URL in the default browser, never the card. At most three show, then `+N`. Forgotten when the shell exits, is Closed or restarted, or the card is deleted; never saved or synced. Not for SSH cards, whose `localhost` is the remote host, and not a preview: nothing is embedded in Drovr.
- **Command palette**: a dialog opened anywhere in the window with its shortcut (Cmd+K on macOS, Ctrl+Shift+P elsewhere, changeable in Settings) that fuzzy-finds every card and shell of every workspace by title, workspace, worktree branch, status and activity, and opens the picked one at full size in its workspace (switching to it and starting it as a click would), and lists the app's existing actions that would do something now (the open card's Back, splits, Close card, Find, moves; New card, Next waiting card, themes, Settings, switching workspace…) with their shortcuts. Not a search of terminal output or files, and not a new way to act: every action is one the app already has. It keeps no query or history across opens or restarts.
- **Shell integration**: the marks a shell sends around each prompt and command (OSC 133, VS Code's OSC 633) and the directory it reports (OSC 7), from which a terminal knows its **commands**: each from the start of its output to its end, on its command line's row, with an exit code. A **failed command** is one that ended with an exit code other than 0; its line gets a red bar and a `✗ <code>` badge. A **long command**, one that ran 10 seconds or more, sends a notification when it ends in a pane the user isn't looking at (`Command finished` or `Command failed (exit <code>)`), when Notifications are on; it is not waiting and changes no activity. A new split of a local card starts in the reported directory; the card's own directory never changes. Runtime only: kept with the terminal's screen and gone with it, never saved or synced. Not an agent's activity, which only `board activity` sets.
