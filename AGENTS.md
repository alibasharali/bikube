# AGENTS.md

Drovr: A kanban board for macOS and Linux where every card is a live terminal, for running many coding agents side by side.

Built with Software Factory's workflow: read `docs/agents/workflow.md` before starting on an item, and `docs/agents/stack.md` for the stack picked at creation and its guidelines. Domain terms are in `CONTEXT.md`, decisions in `docs/adr/`.

## Commands

- `npm ci` installs; `postinstall` rebuilds node-pty for Electron (needs python3, make and a C++ compiler on Linux). Where the Electron headers download is blocked (cloud sessions: postinstall fails with a proxy 403), everything else is installed by then: run `npm rebuild node-pty`; the Node build works in Electron too (N-API, ADR 0001). If `node_modules/electron/dist` is empty afterwards (the failed postinstall can skip Electron's own download), run `node node_modules/electron/install.js`.
- `npm run dev` starts the app with hot reload; `npm start` previews the production build.
- `.claude/check.sh` runs everything that must be green: typecheck, lint, Vitest, build, `node .factory/check-stack.mjs`. CI's `check` job runs it.
- Individually: `npm run typecheck`, `npm run lint`, `npm test` (Vitest), `npm run build`, `npm run format`.
- `npm run test:smoke` builds, then runs the Playwright-Electron smoke tests in `e2e/` (window, no menu bar off macOS, empty state, workspace create/validate/switch/edit/delete, columns, sidebar collapse, keyboard: `e2e/board.spec.ts`; cards create/open/back/status/Stopped and restart/rename/delete: `e2e/cards.spec.ts`; startup commands (new-card select, workspace default, card menu, tags, Claude Code resume with a fake `claude`, a long startup line typed at the fitted size): `e2e/startup.spec.ts`; navigation lock and terminal lifecycle, SIGKILL escalation when a shell ignores the hangup and no shell surviving quit: `e2e/lifecycle.spec.ts`; keyboard, menu and drag moves of cards: `e2e/moves.spec.ts`; closing a card from its menu and the full-size view, cancel, resume after closing, not offered when not running, deletes after closing: `e2e/close.spec.ts`; the board surviving a restart, restored cards Stopped, resume after a restart, SIGKILL, unreadable state file, launch view, one instance per data directory: `e2e/persistence.spec.ts`; the `board` command typed in a card (self and sibling moves, errors, other workspaces, usage, outside a card, the socket's mode and lifetime, bad requests): `e2e/board-cli.spec.ts`; split panes inside a card (split right and down, the shortcuts and the 4-pane limit, plain shells in extra panes, focus, closing a pane, Back keeping the panes, the main shell's stop or Close ending every pane, deletes, `board` from any pane, not kept across a restart, font size in every pane): `e2e/panes.spec.ts`; themes and settings (the Settings dialog and shortcut, light, dark and System themes on the board and terminals, font size and family, kept across a restart, invalid settings file): `e2e/settings.spec.ts`; SSH workspaces (the dialog's Location and Host, the sidebar tooltip, host in the state file and across a restart, cards connecting through a fake `ssh` in the remote directory, the startup command after the ready marker, SSH failed, refused spawns, split panes over SSH, `board` in SSH cards and their extra panes through a forwarded socket (its errors, only its own card, cleanup on exit, quit and launch, a host refusing the forward), a Codex card's first start after the ready marker and its resume on reopen): `e2e/ssh.spec.ts`; sync between machines (the Sync folder setting, writing and joining the board, Turn off, the folder kept per machine; two instances with their own `DROVR_HOME_DIR` reading each other's changes live, deletions keeping a card running on the other, home mapping, Claude Code `--session-id`/`--resume` across machines, a local Codex card starting fresh and an SSH one resuming on the other machine, the active workspace per machine, the launch read, no echo; a removed folder and its recovery, an unreadable file never overwritten; a stalled sync file (a FIFO with no writer) freezing nothing and applying once fed, a change made just before quit reaching the file, a quit with the FIFO left unfed ending the process within two holds, #26): `e2e/sync.spec.ts`; terminal flow control (a stalled renderer catching up without dropped output, stopping and deleting streaming cards, ordinary output unchanged): `e2e/flow-control.spec.ts`; terminal colours (16 ANSI, 256-colour and truecolor cells) and copy and paste in a card: `e2e/terminal.spec.ts`; agent resume presets (Codex, Gemini CLI and OpenCode in the selects, tags, the plain command first and `<resume> || <plain>` after, nothing to resume, switching away and back, the same-directory hint, workspace default, kept across a restart, a state file from before #21): `e2e/presets.spec.ts`; the Shell setting, the terminal theme pickers and Use Ghostty theme (a fake `XDG_CONFIG_HOME` and `HOME`): `e2e/terminal-themes.spec.ts`; the fake `claude` setup is shared in `e2e/fake-claude.ts`, the fake `codex`, `gemini` and `opencode` (one shared log, `FAKE_AGENT_RESUME_FAILS`) in `e2e/fake-agents.ts`, the fake `ssh` (one log line per connection, `FAKE_SSH_DELAY`, `FAKE_SSH_FAIL_AFTER`, `-R` as a real socket at the remote path relaying each connection to the local one (a perl process that exits with the session), `FAKE_SSH_NO_FORWARD` printing ssh's refusal warning instead) in `e2e/fake-ssh.ts`; every test launches through `e2e/launch.ts`, which gives it its own `DROVR_USER_DATA_DIR` and removes it with `removeDataDirs()` after the test, and gives a launch 25 s (`DROVR_E2E_WINDOW_TIMEOUT_MS`) to bring its window and the app's root, else logs the reason and stderr, kills it and launches once more, #23). Needs a display: `xvfb-run -a npm run test:smoke` on Linux. CI runs it after `check.sh`. Playwright pins `prefers-color-scheme: light` in the page and xvfb's OS appearance is light, so a test about the Theme setting must call `page.emulateMedia({ colorScheme: null })` (`followNativeTheme` in `e2e/settings.spec.ts`) and assert something light can't fake (e.g. `nativeTheme.themeSource` from main, or a saved Dark theme).
- `npm run test:packaged` packs the Linux app (`npm run pack`), then runs `e2e/packaged.spec.ts` (`playwright.packaged.config.ts`; not part of `test:smoke`) against `dist/linux-unpacked`: `resources/bin/board` is executable and `resources/app.asar.unpacked/out/main/board-cli.js` exists, then one launch of the packaged `drovr` executable (through `launchApp`'s `executablePath`) that creates a workspace and a card and runs `board status . packaged` in it. Linux only (skipped elsewhere). Needs a display: `xvfb-run -a npm run test:packaged`. CI's `check` job runs it after the smoke tests.
- `npm run benchmark` builds, then runs the 10-terminal performance benchmark (`e2e/benchmark.spec.ts`, `playwright.benchmark.config.ts`): 10 cards in one workspace, all streaming, one open at full size; writes `test-results/benchmark-<profile>.md`. Needs a display: `xvfb-run -a npm run benchmark`; `BENCH_PROFILE=firehose` for the stress profile (unthrottled `yes | cat -n`). The default `sustained` profile asserts the full D8 budget (#1); firehose asserts zero dropped echoes, every session producing output with its status line live, and main event-loop lag p99 within 100 ms, and reports renderer fps and echo max as info (#16 D7). Both tables show the most characters any session had unacknowledged in main (flow control, #16), read from a reader main puts on `globalThis` only when `DROVR_BENCH` is set.
- `npm run dist` builds the release packages for the OS it runs on: the unsigned .dmg on macOS, `drovr-<version>-x86_64.AppImage` and `drovr-<version>-amd64.deb` on Linux (in `dist/`); `npm run pack` builds an unpacked app for the current OS. In cloud sessions both fail at electron-builder's node-pty rebuild (the same proxy 403 as postinstall), and the failed rebuild deletes node-pty's build, breaking Vitest and any package built after it: run `npm run build && npx electron-builder -c.npmRebuild=false` (add `--dir` for the unpacked app) instead, and `npm rebuild node-pty` if it was already wiped.
- CI also runs `actionlint` (via `check.sh`; install with `go install github.com/rhysd/actionlint/cmd/actionlint@v1.7.7`). `.github/workflows/release.yml` runs two independent jobs on a published release (pre-releases too): `dmg` on macOS attaches `dist/*.dmg`, `linux` on Ubuntu attaches `dist/*.AppImage` and `dist/*.deb`; one failing doesn't cancel the other.
- Headless launch: `xvfb-run -a npx electron . --no-sandbox` (after `npm run build`).

## Architecture

- `src/main` Electron main process; `src/preload` the only bridge to the renderer, typed by `src/shared/api.ts` (`window.drovr`); `src/renderer` React UI; `src/core` plain TS with no Electron imports (session/PTY logic), unit-tested with Vitest on Linux.
- `board` (#9): inside a card's terminal (only there), an agent runs `board move <card> <column>` or `board status <card> <text>` (`.` is the calling card; `board help`). `resources/bin/board` (a POSIX sh wrapper; its directory is prepended to PATH in the environment of every card's shell and given as `DROVR_BIN`, so `"$DROVR_BIN/board"` works whatever a profile does to PATH) runs `out/main/board-cli.js` (built from `src/main/board-cli.ts`) with Drovr's own executable as Node; it talks to main over `<userData>/board/board.sock` (a private 0700 directory, the socket 0600), and main forwards each request to the renderer, which applies it to the store. Packaged, `bin/` is in `extraResources` and the CLI module and its chunks are unpacked from the asar (`electron-builder.yml`); after `npm run pack`, `dist/linux-unpacked/resources/bin/board` must be executable and `resources/app.asar.unpacked/out/main/board-cli.js` must exist. In SSH cards (#25) the local shell running `ssh` gets none of this: before each SSH session (main pane or extra pane) main listens on its own `<userData>/board/s-<16 hex>.sock`, serving only that card (`src/core/session-sockets.ts`), and the line becomes `ssh -o ExitOnForwardFailure=no -R /tmp/drovr-<32 hex>.sock:<that socket> -t -- …` (`src/core/ssh-command.ts`); the remote command writes a POSIX sh `board` script running an embedded perl or python3 client (`src/core/remote-board.ts`, no backslashes so it stays fish-safe) into a private `mktemp -d` directory and removes it and the remote socket when the shell ends. Session sockets close when their session exits and on quit; leftovers are removed at launch. Without a local socket ssh gets no `-R`, and the card runs anyway.
- Terminal themes: `src/core/ghostty-themes.json` is Ghostty's 463 theme files (iTerm2-Color-Schemes), rebuilt with `node scripts/import-ghostty-themes.mjs <ghostty>/themes`; "Use Ghostty theme" reads the user's Ghostty config in main (`src/core/ghostty-config.ts`). The bundled `Symbols Nerd Font Mono` (`src/renderer/src/assets/fonts`) is loaded before the first render and appended to every terminal's font family. Their licences are in `THIRD_PARTY_NOTICES` (packaged by `electron-builder.yml`'s `extraResources`): update it when either changes.
- Window settings: contextIsolation on, nodeIntegration off, sandbox on. Don't weaken them.
- Terminal flow control (#16): main pauses a PTY above 100k characters the renderer hasn't acknowledged (`terminal:ack`, sent once xterm has parsed them) and resumes below 5k (`src/core/flow-control.ts`). Every chunk the renderer receives must be acknowledged exactly once (`SessionRouter` + `AckBatcher`), or its shell stays paused. node-pty drops a paused PTY's unread output 200 ms after its shell exits, so `SessionManager` resumes before kill and resumes a paused session whose shell is gone.
- Sync folder I/O (#26): never block main on the sync folder (it may be a stalled network mount or a cloud placeholder). `SyncFolder` uses async fs and runs every operation one at a time on its own queue, so a new operation must go through that queue to keep #13 D4 (no echo) and D12 (never overwrite). A libuv thread stuck in a stalled fs call keeps the process from exiting, so quit SIGKILLs main when sync is still busy at `quit` (`src/core/quit-hold.ts`).
- No macOS-only APIs outside packaging and window chrome (Linux and Windows builds stay possible). node-pty's `kill(signal)` throws on Windows: pass a signal only off `win32` (#18).
- Stack and decisions: `docs/adr/0001-stack.md`. Never deploy by hand; releases come from a GitHub release workflow.

This file is for every coding agent; `CLAUDE.md` imports it.
