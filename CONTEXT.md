# Context

The domain language of Drovr. One entry per term: what it means here, and what it doesn't.

<!-- - **Term**: definition. Not to be confused with … -->

- **Startup command**: what Drovr types into a card's login shell, followed by Enter, right after each start: `Shell` (nothing), `Claude Code` (`claude` with the card's agent session id), or `Custom` (a one-line command run as written). Each card has its own; a workspace's default startup command is only the preset for new cards. Not to be confused with the login shell itself, which every start runs.
- **Agent session id**: a random UUID v4 a card gets at creation and keeps for life, whatever its startup command; Claude Code cards pass it to `claude --session-id` / `--resume` so reopening the card returns to the same conversation. Not the card's id, nor the PTY session id.
- **Stopped**: a card whose shell has exited; its screen and scrollback are gone, and opening it starts it again with its startup command. Replaces #4's "Exited (code N)". Not to be confused with `Couldn't start`, where the shell never ran. An SSH card whose `ssh` fails reads `SSH failed` instead.
- **Close**: stopping a running card's process from its menu or full-size view, after a confirmation; the card keeps its place, title, startup command and agent session id and becomes `Stopped`, so opening it again resumes it. Not to be confused with `Delete`, which removes the card, nor with `Back`, which leaves the process running.
- **Saved state**: the board as Drovr keeps it across restarts in `drovr-state.json`: every workspace, its columns and cards in order, their titles, directories, SSH hosts, startup commands and agent session ids, and which workspace is active. With a **Sync folder** set, the same board (without the active workspace) is also kept there for other machines. Not terminal processes, screens or scrollback: after a restart every card is `Stopped` until it is opened. Not to be confused with UI preferences such as window size or the collapsed sidebar, which are not saved.
- **Board command**: `board`, the command every local card's shell has on its PATH (an SSH card's remote shell doesn't), through which a program in the card tells the board what it is doing: `board move <card> <column>` moves a card of the same workspace (`.` is the calling card) to the bottom of a column, `board status <card> <text>` sets its agent status. It reaches the running app over a socket only the same user can use, and works only from a card with a running shell. Not a global install: outside a Drovr card it isn't on the PATH.
- **Agent status**: a short text a program in a card sets with `board status`, shown in place of the card's last output line while the card is `Running` (`Running · <text>`); empty text clears it. It is cleared when the card's process stops or starts again, and never saved. Not to be confused with the card's status (`Running`, `Stopped`, `SSH failed`, `Couldn't start`), which Drovr derives itself.
- **Settings**: the app-wide preferences Drovr keeps across restarts in `drovr-settings.json`, the same for every workspace and card: the colour theme (`System`, `Dark` or `Light`) and the terminals' font size and family. The same file keeps this machine's **Sync folder**, which is never synced. Not saved state: the board's file is separate and never holds them. Not to be confused with UI preferences such as window size or the collapsed sidebar, which are not saved at all.
- **Pane**: one terminal inside a card's full-size view, which shows 1 to 4 side by side or stacked. The **main pane** is the card's own terminal: its startup command, agent session id and status, the one the board shows. Every other pane is an **extra pane**: a plain login shell in the card's directory with no startup command, which can run `board` for the card (in an SSH card, its own `ssh` session to the card's host and directory, without `board`). Extra panes live and die with the main pane: when it stops, or the card is deleted, they are killed and discarded. Not saved state: after a restart a card has only its main pane. Not a card: an extra pane has no title, status or place on the board.
- **SSH workspace**: a workspace whose cards run on another machine: it has a **host**, a destination exactly as `ssh` takes it (`me@devbox`, an alias from `~/.ssh/config`), and its working directory is a path on that host (absolute or starting with `~`), never checked from the dialog. Each card's terminal runs the user's own `ssh` to the host from the local login shell, `cd`s into the remote directory and runs the startup command there; every extra pane opens its own `ssh` session. A card copies the host with the directory at creation and keeps both for life, so editing the workspace changes new cards only. A workspace without a host is local. Not a sync: the board, its saved state and settings stay on this Mac, nothing is copied to or from the host, and remote cards have no `board` command.
- **SSH failed**: the status of an SSH card whose `ssh` exited by itself with code 255 (host unreachable, authentication failed, connection dropped, remote directory missing): `SSH failed: <last output line>`. Otherwise it is like `Stopped` (screen gone, opening it connects again), and after a restart it is `Stopped`; an extra pane whose `ssh` fails keeps its screen with `SSH failed` below it until closed. Not `Stopped`, which is any other exit or a stop by Close, delete or reload; not `Couldn't start`, where Drovr never ran the shell at all.
- **Sync folder**: a folder the user picks in Settings, which their own file sync tool (iCloud Drive, Dropbox, Syncthing…) carries between machines; Drovr reads and writes one file in it, `drovr-board.json`, holding the board: every workspace, column and card, with local directories under the home directory written as `~`. Turning it on joins the folder's board with this machine's; after that the last machine to change the board wins, and a change reaches the other open machines live (read at launch, when the folder changes and on window focus). A sync never stops or removes a card running on this machine: it stays, and is written back. Kept per machine (in `drovr-settings.json`), never synced itself. Not a Drovr server or network sync, and not the saved state: settings, the active workspace, processes, scrollback, panes and agent status stay on each machine, and a synced card is `Stopped` on a machine until opened there.
